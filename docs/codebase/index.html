02 / OWNERSHIP MAP

Where should a change go?

RULES

Simulation

GameState, CityState, GameSetup, scoring, weapon and technology catalogs. Keep calculations deterministic and free of Android and libGDX types.

DECISIONS

AI

OpponentAI selects and scores opponent actions. Change choices here; resolve their effects in GameState.

PRESENTATION

Game + UI

WorldDominationGame handles drawing, viewport layout, input routing, and lifecycle. ScrollPaneState and MatchOutcomePresentation hold UI behavior.

RESOURCES

Assets + audio

OriginalUiAssets maps image regions and releases them. OriginalAudio loads and plays the original sound cues.

Extension ruleStart with a focused deterministic test for a new rule. Add state and resolution in simulation, then expose the choice in UI. Reuse original artwork and keep all gameplay offline.

04 / PRACTICAL WORKFLOW

Make a safe contribution.

  1. Trace ownershipFind the symbol here, open its source, and follow the caller and state it touches.
  2. Use a task branchKeep changes isolated from protected main and from other agents' worktrees.
  3. Verify parityCompare gameplay rules with the read-only Python reference and keep mapping notes local.
  4. Run the gatesAssemble debug, run debug unit tests, and run lint before opening a PR. Verify visual changes on a device when possible.
