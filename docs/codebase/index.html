2. How the code flows

There are four main steps in a typical interaction. The Android and libGDX layers own presentation and input. GameState owns deterministic game rules.

  1. Android starts the game

    MainActivity creates the libGDX application, applies immersive mode, and forwards safe area insets. Find MainActivity.

  2. The frame advances

    WorldDominationGame.render() advances the fixed 24 Hz presentation clock and draws using cached libGDX resources. Find WorldDominationGame.

  3. Input selects an action

    The game routes taps and drags. ScrollPaneState keeps navigation and equipment scrolling independent. Find ScrollPaneState.

  4. The turn resolves

    GameState validates and queues actions. confirmTurn() resolves orders, consults OpponentAI, and updates match status. Find GameState.

3. Where to make changes

Use the owner of the behavior as your starting point. Keep simulation independent of Android and libGDX classes.

Rules and game state
game.simulation contains GameState, CityState, GameSetup, scoring, and the weapon and technology catalogs. Put calculations and turn effects here.
Opponent decisions
game.ai.OpponentAI selects and scores actions. Resolve their effects in GameState.
Presentation and interaction
WorldDominationGame handles drawing, layout, input routing, and lifecycle. game.ui holds independent scroll state and outcome presentation.
Images and sound
game.assets.OriginalUiAssets maps original image regions. game.audio.OriginalAudio loads and plays original cues.
Adding a new game rule

Start with a focused deterministic test. Add the rule to simulation, expose the choice through the UI, and compare its behavior with the read-only Python reference.

5. Contributor workflow

  1. Find the owning class in the reference and follow the caller and state it touches.
  2. Make changes on a task branch, leaving protected main and other agents' worktrees alone.
  3. Compare gameplay rules with the read-only Python reference. Keep parity notes local.
  4. Run Android assembly, unit tests, and lint before requesting review. Verify visual changes on a device when possible.
gradlew.bat :app:assembleDebug
gradlew.bat :app:testDebugUnitTest
gradlew.bat :app:lintDebug

Refresh the reference

After changes reach main, install docs/codebase/requirements.txt, run python docs/codebase/generate.py, and review the resulting api.json diff. The generator reads application source and writes only this documentation index.
